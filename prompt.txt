================================================================================
1. WHAT "DAILY LIFE" MEANS HERE
================================================================================

Not abstract dev utilities for their own sake — tools that solve a concrete
task someone hits mid-task, this week, doing real work:
  - a stock/content contributor prepping an asset for submission
  - someone renaming/organizing files before uploading them somewhere
  - someone saving a snippet of text/code/config as a real file without
    installing anything
  - someone cleaning up a filename, image, or document before publishing it
  - someone converting between formats a specific platform demands
  - someone double-checking a file meets a specific site's requirements
    before submitting it (size, resolution, transparency, naming rules)

That's the shared DNA across all four reference tools above: "I have a file/
text right now and need to get it into the exact shape a specific real-world
destination requires." Build more tools in that spirit.

--- TIER 1: Direct extensions of the 4 reference tools (build these first) ---

1. Stock Asset Readiness Checker (generalized version of Stock PNG Lab) —
   upload an image, auto-check: resolution >= common stock minimums (e.g.
   4MP/3000px), file format, transparency presence/absence, aspect ratio,
   estimated file size vs platform limits (Adobe Stock / Shutterstock /
   Freepik / Envato presets user can pick from a dropdown). Manual checklist
   for things that can't be automated (logos, faces, watermarks — mirror the
   existing Stock PNG Lab checklist, don't invent new rules).
2. Batch File Extension / Renamer Tool (generalize file-tool.html) — select
   multiple files, rename extension OR full filename pattern (prefix/suffix/
   sequence numbering), export as ZIP [JSZip]. Keep the existing tool's
   "select folder, change, download" flow.
3. Universal File Saver (native OmniTools rebuild, inspired by the existing
   Blogger version's feature set — do not link to or embed the Blogger
   page) — textarea + category-grouped extension picker (Code / Documents /
   Data / Config / Other) + quick templates (README, HTML boilerplate,
   JSON skeleton, .env template, etc.) -> Blob download with correct
   extension, built entirely as a new /tools/universal-file-saver/ page
   using OmniTools' own template and design system.
4. SEO-Friendly Filename Generator (native OmniTools rebuild, inspired by
   the existing Blogger version's feature set — do not link to or embed the
   Blogger page) — text in, slugified filename out, with toggle options
   (lowercase, spaces->underscores or hyphens — offer both, strip special
   characters, trim). Keep an example-conversions block, it's good UX.
   Built entirely as a new /tools/seo-friendly-filename-generator/ page.
5. Stock Photo Metadata Generator — paste an image description, get a
   platform-ready title (10-12 words), 45-55 word description, and a
   50-keyword comma list — built from an on-device template/heuristic
   generator (word-relevance expansion from the description text, NOT a
   live paid AI call). Label clearly as "starter draft — review before
   submitting," this replaces the manual ChatGPT-prompt step from Stock
   PNG Lab's workflow with something that runs in-page.
6. AI-Generated Image Disclosure Helper — small utility that appends the
   correct "AI Generated / AI Assisted" metadata note per platform (Adobe
   Stock / Shutterstock / Freepik each phrase this differently) so
   contributors don't forget the checkbox Stock PNG Lab warns about.
7. Image Background Edge Checker — upload a PNG with transparency, preview
   it composited over several solid background colors (red/black/white/
   checkerboard) side by side, exactly like Stock PNG Lab's halo-detection
   step, so users catch bad background removal before submitting anywhere.
8. File Type Detector / Validator — drop any file, tool reads magic
   bytes (not just the extension) and reports the REAL file type, flags
   mismatches (e.g. a .jpg that's actually a PNG) — the natural companion
   to the extension changer, since renaming doesn't fix an actually-wrong
   format.

3. ARCHITECTURE RULES (unchanged from the existing repo conventions)
================================================================================

- Every tool lives at /tools/<kebab-case-slug>/ (index.html, style.css,
  script.js), built by copying /templates/tool-template/ and following the
  same pattern as the 10 existing tools (breadcrumb, JSON-LD
  SoftwareApplication + BreadcrumbList schema, About/How-to-use/Features/
  FAQ/Related-tools sections).
- Register each tool as ONE object appended to data/tools.json (id, name,
  slug, category, icon, description, keywords, featured, isNew). Never
  hand-edit homepage/category HTML to list a tool — render.js already does
  this from the JSON file.
- Reuse assets/css/*.css and assets/js/main.js + render.js as-is. Add
  tool-specific styling only to that tool's own style.css. If a genuinely
  new shared interaction is needed (e.g. batch ZIP export helper used by
  several tools), put it in a new assets/js/helpers/zip-export.js and
  import it from each tool's script.js — don't copy-paste the same helper
  into five files.
- Every new tool: zero console errors, works keyboard-only, ARIA labels on
  custom controls (dropzones, canvases, sliders), responsive at 360/768/
  1440px, correct in both dark and light theme, and shows up correctly in
  its category page + site search + related-tools.
- Regenerate sitemap.xml after adding tools (script it, don't hand-type).
